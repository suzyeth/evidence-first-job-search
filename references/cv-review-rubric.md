# CV 评估规则书(cv-review rubric)

> 每份简历**渲 PDF 之前**跑一遍。评估器输出五维评分 + 改进清单,按清单改完再渲。
> 事实权威:`master-cv-data.md`;风格权威:`tone.md`;JD 权威:对应包的 `JD.md`。

> 机器部分先交给 `fact_check.py`(数字 / 技能 / 指标溯源 + 保密词 + 占位符 + 空话),它过了再按下面五维人工评审。

## ⚙️ 使用者需自填:保密项清单(B 维 grep 用;同一份清单写进工作区的 confidential-terms.txt 供 fact_check.py 使用)

## 五维评估

### A. JD 对齐(对着 JD.md 的 5-signal 表打分)
- [ ] Summary 前 10 词内出现 JD 的 title 级关键词
- [ ] JD 的每条 Required / Min quals,简历上有**可指认的证据位置**(逐条列出"要求 → 简历第几节哪一行")
- [ ] JD 的职责动词在 bullet 动词里有呼应
- [ ] 该 JD 的 top-3 卖点排在各自分区首位,而不是埋在中间
- [ ] 对这家公司是噪音的内容已删

### B. 真实性红线(一票否决,逐条 grep)
- [ ] 每个事实可溯源到 master-cv-data.md;无 master-cv 之外的新声明
- [ ] 上方保密项清单零出现
- [ ] 指标措辞与 master-cv 完全一致(不改写成别的指标)
- [ ] 完成度诚实:没完成的项目/比赛不以"已交付/参赛作"框架呈现
- [ ] 署名诚实:solo 是 solo,团队标团队,fork 只声称自己做的那层
- [ ] 无 buzzword(passionate / driven / leveraged / spearheaded)· 无 `[FILL]` 残留

### C. 6 秒扫描层(招聘官视角)
- [ ] 首句读完知道"这人是谁、投的什么"
- [ ] 每个 bullet 首词是动词;每个项目标题行自带一句话卖点
- [ ] 数字密度:每屏至少 3 个可验证数字
- [ ] 页数 ≤ 2;分区标题让人 3 秒建立结构
- [ ] 奖项 / live 链接等最强信号有视觉权重

### D. ATS / 文字层
- [ ] PDF 文字层可提取,关键技能词至少各有一处完整未断行出现
- [ ] 链接全部可点且指向活页面(投前逐个点)
- [ ] 文件名规范:`<First>_<Last>_Resume_<Company>.pdf`(无空格)
- [ ] 教育 / 时间线完整,无断档误导

### E. 差异化(竞品池视角)
- [ ] 假想该岗申请池的典型画像,列出"我有而典型候选人没有的 top-2" —— 是否排到最显眼处
- [ ] 诚实 gap 是否有面试答案(不上简历,答案记在包的 JD.md 里)

## 输出格式
1. 五维各判:✅ 通过 / ⚠️ 有改进项 / ❌ 一票否决(B 维 ❌ 置顶)
2. 改进清单:按影响排序,每条给"改什么、改成什么、为什么"
3. 一句话总评:这份简历在该岗申请池里的相对位置
