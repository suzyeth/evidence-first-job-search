## 开始填写

1. 选择一个岗位，保存JD原文和来源。教学练习可用示例JD，但它不是实际招聘。
2. 在自己的私有岗位文件夹建立工作副本；只复制各文件“空白模板”区。保留本目录作为可复用母版。
3. 指定已有事实库路径。不要把虚构示例复制进真实履历，也不要在技能仓库保存私人履历。
4. 按 R要求 → E事实 → B简历条目 → S故事关联；在面试提纲中引用编号。
5. 有疑问的事实先标待确认。真实定稿再进行既有事实检查和CV评审。

示例采用同一虚构初级工具开发岗位，方便观察四份文件如何相互衔接。它更贴近游戏/工具开发场景，但表格可以用于其他岗位。示例中的数字、日期、项目、公司和文件名都是教学内容，并不是已经生成的项目证据。

## 七天执行建议

| 天 | 任务 | 验收 |
|---|---|---|
| 1 | 拆JD与条件 | 未知项明确；没有把加分当必备 |
| 2 | 盘点真实证据 | 每项有事实库定位 |
| 3 | 改写CV | 每条能解释动作、结果与归属 |
| 4 | 建立故事卡 | 优先完成3个最相关故事，再补覆盖缺口 |
| 5 | 准备回答 | 区分公司事实、个人经历、未来计划 |
| 6 | 录音模拟追问 | 找出最弱的两个回答 |
| 7 | 修改并重练 | 确认有具体改善，不追求背稿一致 |

## 可以直接交给AI的任务

“阅读我的事实库和这个JD，用01、02模板列出岗位要求与改写建议；没有证据的内容标待确认，不补造经历。”

“根据我的已有故事草稿，用03补齐行动、判断和结果边界。缺少的事实逐项问我，不把问题答案自行填成经历。”

“根据04和目标JD模拟面试，一次问一道题，等我回答后追问，再对切题、证据、取舍和表达给具体反馈。”
